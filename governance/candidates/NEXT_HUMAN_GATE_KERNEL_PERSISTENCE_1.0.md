# NEXT HUMAN GATE — KERNEL PERSISTENCE

DECISION_REQUIRED: choose how to obtain a complete exact deployable non-constitutional Kernel payload set suitable for Git cold-start reconstruction.

WHY_HUMAN_JUDGMENT_IS_REQUIRED:
The governed execution surface can identify current exact hashes and File Library locators but cannot guarantee complete byte-for-byte export of every ACTIVE payload, especially UAO 1.7. Creating substitute bytes would violate exact identity. The remaining alternatives have materially different lineage semantics.

OPTIONS:
A. RECOVER_CURRENT_EXACT_PAYLOADS — Human makes the exact complete current ACTIVE payloads available through a byte-complete source (preferably Git or an uploaded archive). Preserve current identities and migrate without semantic change.
B. BUILD_SUCCESSOR_KERNEL_SET — Treat current File-Library-only identities as legacy rollback lineage and build a new complete Git-native successor set, then perform full semantic/contradictory qualification and G2 promotion.

RECOMMENDATION: A if exact payloads are recoverable; otherwise B. Do not approximate current bytes.

MATERIAL_CONSEQUENCES:
A minimizes semantic change and qualification surface.
B is cleaner long term but constitutes new deployable kernel identities and requires deeper G2 qualification.

CURRENT_ACTIVE_STATE: unchanged on main; candidate work exists only on branch candidate/kernel-persistence-cold-start-v1.

SAFE_RESUME_CONDITION:
A byte-complete exact payload source is available, or the human explicitly chooses successor construction.
